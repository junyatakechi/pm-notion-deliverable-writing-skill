# 文書の変更履歴の書き方

[SKILL.md](../SKILL.md) の「6. 文書の変更履歴に記録する」で、行を足す前に読む。

## 列

列は少なく保ち、それ以外はすべて本文に書く。行を足すたびに埋める欄が多いと、記録そのものが重くなるため。

| 列 | 型 | 書くこと |
|---|---|---|
| `変更内容` | タイトル | 何をどう変えたかを1文で書く（例「〜を1箱に戻した」「〜をやめた」） |
| `日付` | 日付 | 決めた日時。時刻まで入れる |
| `文書` | リレーション | 書き替えたDeliverableのページを1つ。必ず付ける |
| `版` | テキスト | 題名に `_vX.Y.Z` があれば、書き替えたあとの版。無ければ空にする |

- `日付` の時刻は日本時間で、行を足す直前に次の1行で取る。記憶やシステムの日付に頼らない。
  ```bash
  python -c "import datetime as d; print(d.datetime.now(d.timezone(d.timedelta(hours=9))).strftime('%Y-%m-%dT%H:%M:00+09:00'))"
  ```
- 公式MCPで書くときは `"date:日付:start": "<取った日時>"` と `"date:日付:is_datetime": 1` を渡す。`is_datetime` を省くと0として扱われ、日付だけになる。
- `日付` をページの作成日時（`Created time`）で代えない。過去の行は後からまとめて取り込んだものがあり、作成日時と決めた日が一致しないため。
- `ID`・`Created time`・`Last edited time` は自動で入るので書かない。
- 変更の大きさは `版` の上がった桁で読む。

## 本文

本文は、as-is・to-be・理由の3列の表だけにする。データベースの既定のテンプレートも同じ形になっている。

```markdown
| as-is | to-be | 理由 |
|---|---|---|
| 変える前の状態 | 変えたあとの状態 | なぜ変えたか |
```

- 1つの決定で変えたことが複数あれば、表の行を増やす。決定そのものが2つあるときは、変更履歴の行を分ける（→SKILL.md の6）。
- 新しく足した規則など、変える前に何も無かったときは、as-is に「なし」と書く。
- 理由には、そう決めたきっかけの出来事を具体的に書く。次に読むときに「この前提は今も成り立つか」を確かめられるため。
- 本文に書くときの落とし穴は [notion-pitfalls.md](notion-pitfalls.md) と同じ。ファイル名はコード表記にする。

## 決定を覆すとき

足した行は書き替えない。覆すときは新しい行を足し、as-is に前の決定を、to-be に新しい決定を書く。前の行が見つかるなら、as-is のセルにその行へのメンションを添える。

## 読み方

- 文書のページの `変更履歴` リレーションに、その文書の行がつながっている。
- 一覧を取るときは `notion-query-data-sources` で `文書` を絞り、`変更内容` と `日付` で見当を付ける。中身は本文にあるので、関係する行だけ `notion-fetch` で開く。
- 2026年10月より前の行は形が古い。本文の先頭に `節:` などの行があり、その下に `## 理由`・`## 却下した案`・`## 根拠` の見出しがある。先頭に `置き換え先:` か `取り消し:` がある行は、もう生きていない決定。
