# 文書の変更履歴の書き方

[SKILL.md](../SKILL.md) の「6. 文書の変更履歴に記録する」で、行を足す前に読む。

## 列

| 列 | 型 | 書くこと |
|---|---|---|
| `決定` | タイトル | 何を決めたかを1文で書く（例「〜を1箱に戻す」「〜をやめた」） |
| `日付` | 日付 | 決めた日 |
| `文書` | リレーション | 書き替えたDeliverableのページ。必ず付ける |
| `版` | テキスト | 題名に `_vX.Y.Z` があれば、書き替えたあとの版。無ければ空にする |
| `節` | テキスト | 決定が効く節（例 `2-3. 名前の付け方`） |
| `種類` | セレクト | 下の表から1つ選ぶ |
| `状態` | セレクト | 足すときは「有効」。覆されたら「置き換え済み」、決定ごと取り消したら「取り消し」 |
| `置き換え先` | リレーション（自己） | 古い行に付け、新しい行を指す。`置き換えた元` は自動で入る |
| `Issue` | リレーション | ユーザーがきっかけのIssueを示したときだけ付ける |

| 種類 | 選ぶとき |
|---|---|
| 値の変更 | しきい値・数値・設定値を変えた |
| 定義の追加 | 新しい定義や規則を足した |
| 語彙の変更 | 語や名前を変えた |
| 構造の変更 | 章立て・置き場・仕組みの形を変えた |
| 限界の追加 | できないこと・測れないことを書き足した |

## 本文

理由・却下した案・根拠は、プロパティではなく本文に書く。長い文章はプロパティの欄では読みにくいため。

```markdown
## 理由
なぜそう決めたか。

## 却下した案
- (1) 選ばなかった案: 選ばなかった理由
- (2) 選ばなかった案: 選ばなかった理由

## 根拠
当時の実測や出来事。件数・日付・確かめた資料。
```

- 比べた案が無いときは、`## 却下した案` の節ごと省く。
- 根拠には具体的な出来事を書く。いつ何が起きてそう決めたのかが残っていると、次に読むときに「この前提は今も成り立つか」を確かめられるため。
- 本文に書くときの落とし穴は [notion-pitfalls.md](notion-pitfalls.md) と同じ。ファイル名はコード表記にする。

## 読み方

- 文書のページの `変更履歴` リレーションに、その文書の行がつながっている。
- 一覧を取るときは `notion-query-data-sources` で `文書` と `状態` を絞る。理由・却下した案・根拠は本文にあるので、関係する行だけ `notion-fetch` で開く。
