# 一般名詞で書く

[SKILL.md](../SKILL.md) の「一般名詞で書く」の詳細。文書はほかの環境でも使えるように、具体的な名前を一般名詞かプレースホルダで書く。ユーザーが非公開の文書だと指示したときだけ、具体的な名前で書く。

## 対象

- 本文に書くすべての語。新しく書くときも、推敲するときも、コードや設定を貼るときも当てはめる。
- プロパティ・リレーション・コメントは対象にしない。ページそのものを公開すると言われたときだけ確かめる。

## 一般名詞にするもの

| 対象 | 例 | 書き方 |
|---|---|---|
| 自分のスキルやツールの具体的な名前 | 実在するスキル名 | `example-skill`・`<skill-1>`・`<領域>-domain-skill` |
| GitHub などのユーザー名 | リポジトリURLのユーザー名 | `https://github.com/<user>/<skill-1>.git` |
| 個人の用途が分かる名前 | 家計・健康・取引先の名前が入ったキー名や例 | `NOTION_TOKEN_<SKILL>`・`<SKILL>_DB_URL`・`<DOMAIN>_CALENDAR_ID` |
| 非公開のページへのリンクやメンション | Log やほかの Deliverable へのメンション | リンクを置かず、「この文書では扱わない」のように文で言い換える |
| 秘密情報の値 | トークン・パスワード・プロファイル名 | `<SERVICE>_TOKEN=<トークン>`・`<SKILL>_<SETTING>=<設定値>` |
| 名前・メールアドレス・ローカルの絶対パス | `C:\Users\<名前>\...` | `~/...`・`<user>` |

秘密情報の値は、非公開の文書でも実値を書かない。

## 残してよいもの

- 広く使われる一般的な例。`NOTION_TOKEN`・`YOUTUBE_API_KEY`・`MYSQL_PASSWORD` など。
- 公式ドキュメントや公開されている Issue へのリンク。
- 製品名・バージョン・確かめた日付。

## 既存の文書を一般名詞に直す手順

1. 本文を `notion-fetch` で読み、上の表に当たる語を洗い出す。
2. 置き換えの一覧を作り、`update_content` でまとめて置き換える。
3. 読み直し、置き換える前の語が本文に残っていないかを確かめる。
4. 置き換えたものと、残したものとその理由を、表でユーザーに伝える。
